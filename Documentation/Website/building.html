Building

Dependencies, and the commands to build and test.

What has been tried

Everything builds on Red Hat Enterprise Linux: the SDK, the engine, the audit command and the audit window. The commands below were run there. The Windows setup program is cross-compiled there too, and has been run under Wine and on Windows 11 (see Windows). macOS has not been tried, and the macOS package names have not been checked. The application builds, and has been driven end to end on demonstration data in a headless compositor (see Taking the screenshots), but not yet used on a real screen with a real account.

What you need

  • A C11 compiler
  • Meson and Ninja
  • GTK 4.10 or newer (the application)
  • GLib, GIO and json-glib
  • The Railway CLI, needed at run time (the SDK unit tests use a fake one)

Build and test

meson setup build
meson compile -C build
meson test -C build

A clean build produces no warnings. The test run reports the SDK tests, the engine tests, the audit command test, and a live suite that needs Docker (see below). The tests that exercise the real transport use a fake railway script and run on Linux and macOS only. None of the tests use the network.

The live database check

meson test -C build --suite live

This checks the set aside database code against a throwaway PostgreSQL in a container (bound to 127.0.0.1 only). It is skipped if Docker is missing, and the audit does not need it. The default test run does not include it.

Install and run

meson install -C build

This installs two programs, the man pages, and a copy of this website:

ProgramWhat it is
railway-variable-auditorThe audit window (GTK 4).
railway-variable-auditThe same audit without a window. Sign in first with railway login.

Installing the dependencies

Red Hat Enterprise Linux

sudo dnf install gcc meson ninja-build gtk4-devel json-glib-devel
npm i -g @railway/cli

macOS

brew install meson gtk4 json-glib railway

Microsoft Windows

The Windows build is cross-compiled on Linux and packaged as a per-user setup program. See Windows. Building on Windows itself (MSYS2) has not been tried.

Package names

The package names above have not been checked against each platform’s package manager. The libraries themselves are confirmed to build and link on Red Hat Enterprise Linux.

Building an RPM

For Rocky Linux 10 and other Red Hat Enterprise Linux 10 systems. The spec file is Packaging/railway-variable-auditor.spec.

sudo dnf install rpm-build meson gcc glib2-devel json-glib-devel gtk4-devel desktop-file-utils
Packaging/build-rpm.sh
sudo dnf install Packaging/dist/railway-variable-auditor-0.1.0-8.el10.x86_64.rpm
  • What is in it. The window and the audit command, the man pages, this website (under /usr/share/doc/railway-variable-auditor/Website), a menu entry and an icon, and the licence.
  • The tests run during the build. The package build runs the unit tests and validates the menu entry, and fails if either fails.
  • The Railway CLI is not in the package. It has no RPM. Install it yourself (npm i -g @railway/cli) and run railway login. The program tells you if it is missing.

Taking the screenshots

The screenshots on this website are taken by the program itself, so they stay true to the window and can be made again in one command whenever the window changes.

Source/Tools/make-screenshots.sh
  • It builds a special version. The Meson option -Dautomation=true adds a demonstration mode and a screenshot driver. A normal build does not have them.
  • Demonstration data only. --demo replaces Railway with a built-in stand-in holding invented data for an invented company. It does not run the Railway CLI, does not read or change your policy file, and writes only to a temporary folder. Nothing on your account is touched, and no real name can end up in a screenshot.
  • Nothing appears on your screen. The script starts a private, headless Wayland compositor (mutter --headless) and runs the window inside it, with the software renderer.
  • The window drives itself. --screenshots DIR walks through every screen: start, reading, the results, the results after an audit that could not read one project. It saves a PNG of each, using GTK’s own offscreen rendering, and quits.
  • It exercises the real engine. The audit runs for real against the stand-in, and writes real files to a temporary folder, so a broken screen shows up here.

It needs meson, ninja, mutter and dbus-run-session. By default it writes to Documentation/Website/assets/img/app. Look at the pictures after each run: they have already shown real problems in the window.

You can also try the demonstration by hand, on a screen, with a build made with -Dautomation=true:

railway-variable-auditor --demo
