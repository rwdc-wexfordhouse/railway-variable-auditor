Security

How the login and the values are handled, how to look after the audit file, and what the tool cannot do for you.

The short version

The Railway login and the variable values are the most sensitive things this tool touches. The tool never sees your token. Values stay in memory, are wiped when freed, and are never printed or logged. The one file that holds live secrets is audit.csv, and you must look after it.

The login

  • You sign in with railway login, a browser sign-in as yourself. That login reaches every workspace you can access, and so it can read every variable you can. Run railway logout when the work is finished.
  • The tool never sees the token. The Railway CLI holds it, and the tool does not read the CLI configuration file. If a token is ever supplied for headless use, it goes to the CLI through its environment only, never an argument.
  • Nothing is ever written to Railway. The audit only reads. It sends no mutation, so it cannot change or redeploy anything.

Variable values

  • Values are wiped when their table is freed, and request and response bodies are wiped after use. Values are never put in error messages or logs.
  • The window never shows a value. The command line never prints one.
  • No variable value is written anywhere except audit.csv.

Network

Requests go through the Railway CLI, which makes the HTTPS connection to Railway and checks the certificate. Responses are treated as untrusted input: lengths and shapes are checked, and a malformed response is an error, not a guess.

The audit file

It contains live secrets

audit.csv holds the current value of every variable you can read, in one file. It is created readable only by you (mode 0600 on Linux and macOS, a restricted access list on Windows), inside a run folder that is also owner only. Anyone who reads it can use every key in it until you rotate them.

  • Store it on an encrypted disk. Do not email it, put it in a shared folder or a ticket, or paste it into a chat.
  • Treat a copy like the original. Opening it in a spreadsheet may leave autosave and recovery copies elsewhere. Remove them too.
  • Delete it when you have finished. Once everything is rotated, the old values are worth nothing to you and a lot to an attacker.
  • Values may be copied from other values. A pasted database password appears in more than one row. Rotating one is not enough.

What the tool does not do

  • It does not rotate anything. It lists. You rotate each key with its provider, and set the new value in Railway.
  • It cannot read sealed variables. Railway may hide their values from the API. They appear with an empty value. Rotate them by hand.
  • It does not change database credentials. Railway says to use Regenerate on the database service and not to edit the variable by hand. See the checklist.
  • It does not rotate private registry credentials, which Railway also advises rolling. They are not variables. Do this by hand.
  • It does not review logs. Railway advises reviewing the logs of your services for unusual activity. Do this by hand.
  • It does not remove the old values from Railway’s history. Ask Railway what they retain.
