SDK reference

The C11 Railway SDK: every function, error code and rate limit rule.

Who this page is for

Developers of the application. The same content is in the man pages railway(3) and rvcore(3). The SDK is C11 and uses GLib, GIO and json-glib. It needs the Railway CLI at run time. Calls block, so run them off the GUI thread. One client must not be used from two threads at once.

Overview

The SDK sends GraphQL operations to the Railway public API through the Railway CLI (railway api). The user signs in with railway login, a browser sign-in as themselves that reaches every workspace they can access. The SDK never sees the token. It handles paging, rate limits and retries, and gives typed access to the calls the application needs.

  • Secrets stay off the command line. The query text goes to the CLI as an argument. The variables, which carry secret values, go on standard input with --variables @-.
  • The transport can be swapped with rw_client_set_transport(). The unit tests use a mock transport, and also a fake CLI script to check the real transport.
What the audit uses

The audit uses only the read calls: workspaces, projects, services, environments and variables. The write calls (rw_upsert_variables and rw_redeploy_service) are part of the SDK and are tested, but no program calls them.

Listing

These return a GPtrArray of RwEntity (an id and a name), freed with g_ptr_array_unref(). Pages of 100 are followed until none remain. If Railway reports another page without a new cursor, the call fails with RW_ERROR_PARSE rather than looping.

  • rw_list_workspaces(client, &error)
  • rw_list_projects(client, workspace_id, &error): one workspace at a time. Railway lists nothing useful without a workspace.
  • rw_list_services(client, project_id, &error)
  • rw_list_environments(client, project_id, &error)

Variables

  • rw_get_variables(client, project, environment, service, unrendered, &error) returns a hash table of name to value. A NULL service means the shared variables of the environment. With unrendered set, references such as ${{Postgres.DATABASE_URL}} come back as written.
  • rw_upsert_variables(client, project, environment, service, table, skip_deploys, &error) writes the whole table in one request. A NULL service means shared variables. It never replaces: variables missing from the table are left alone. An empty table fails and sends nothing. Railway must answer true, or the call fails.
  • rw_redeploy_service(client, service, environment, &error) redeploys a service in an environment so that it picks up changed variables. It uses serviceInstanceRedeploy, which redeploys what is already deployed. It avoids serviceInstanceDeploy, which can build the latest commit and change the code that runs.
  • rw_variables_new() makes a table whose values are wiped when it is freed. Use it to build the table for an upsert.
Write once per service

Use one rw_upsert_variables call for each service and environment, with skip_deploys set. Then deploy once at the end. This keeps the request count low and stops containers redeploying on every write.

Errors

Errors are returned in a GError with the domain RW_ERROR.

CodeMeaning
RW_ERROR_INVALIDBad arguments, such as an empty variable table.
RW_ERROR_NETWORKRailway could not be reached after the retries.
RW_ERROR_HTTPAn unexpected HTTP status, such as a persistent 5xx.
RW_ERROR_AUTHHTTP 401 or 403, or a GraphQL error saying the request is not authorised.
RW_ERROR_RATE_LIMITEDThe quota is used up. Save progress and resume later.
RW_ERROR_CLIThe Railway CLI is missing, could not be run, or failed in an unrecognised way. Not retried.
RW_ERROR_GRAPHQLRailway returned errors. The message is Railway’s first error message.
RW_ERROR_PARSEThe response was not the expected shape.

Rate limits and retries

PlanPer hourPer second
Hobby1,00010
Pro10,00050
  • On HTTP 429 the client backs off and tries again. The CLI does not pass on Retry-After, so the wait is 1, 2, 4, 8 and 16 seconds.
  • If the wait is longer than the maximum, or the retries run out, it fails with RW_ERROR_RATE_LIMITED so the caller can save its progress and resume later. Because the CLI gives no header, the tool counts its own requests to stay under the hourly quota.
  • HTTP 5xx and network failures back off for 1, 2, 4, 8 and 16 seconds, then 30 seconds.

Example

RwClient *client = rw_client_new(NULL);   /* uses the railway login */
GError *error = NULL;
GPtrArray *workspaces = rw_list_workspaces(client, &error);

if (workspaces == NULL) {
    g_printerr("%s\n", error->message);
    g_clear_error(&error);
} else {
    for (guint i = 0; i < workspaces->len; i++) {
        RwEntity *w = workspaces->pdata[i];
        g_print("%s  %s\n", w->id, w->name);
    }
    g_ptr_array_unref(workspaces);
}
rw_client_free(client);

The engine (rvcore)

The engine sits on top of the SDK and is what the audit window and the audit command use. Header rvcore.h, library librvcore.a, man page rvcore(3). It uses the prefix rv_. Calls block, so run them off the GUI thread.

What the audit uses

StepFunctionsWhat it does
Discover and readrv_discover, rv_topology_estimate, rv_read_variablesLists workspaces, projects, environments and services, says how many requests reading will need, then reads every variable (unrendered). A project that cannot be read is dropped completely and reported as failed. Anything skipped or failed makes the inventory incomplete.
Classifyrv_classifySets the category and the reason of every variable. Only a hint for the reader. See the categories.
Writerv_audit_save, rv_write_audit, rv_audit_default_folderMakes a run folder (owner only) and writes one file, audit.csv (owner only, holds values). rv_audit_default_folder gives the Desktop, or the home folder if there is none. The window and the command line both call these, so they cannot differ.
Policyrv_policy_load, rv_policy_skip_workspaceRemembers workspaces to skip, and extra names that mark a database credential or an internal secret.

What is set aside

The engine also holds code for planning a rotation, staging new values, deploying, undoing, and changing database role passwords through a secure tunnel (rv_plan_build, rv_run_stage, rv_run_deploy, rv_undo_run, rv_run_roles and their helpers). It was written and tested, then set aside because rotating by machine proved too complex to trust during an incident. No program uses it, it is not installed as a feature, and it is not documented as one. Its tests still run, so it stays in working order if it is needed again.

Errors use the domain RV_ERROR. Railway errors keep the domain RW_ERROR.

Testing

The SDK has 31 unit tests. They replace the transport with canned responses, and some use a fake railway script that records how it was called, to prove that secret values go on standard input and never in the arguments.

The engine has unit tests that run against a fake, in-memory Railway. For the audit they cover scanning, classifying, a project that fails, the audit file (a value with a comma, a quote and a line break must come back exactly, and the file must be owner only) and the run folder. The same suite still tests the set aside rotation code.

The audit command has an end to end test: a fake railway program with invented data for two workspaces. It checks that only audit.csv is written, that it is mode 0600, that a tricky value survives, and that no value reaches the terminal. Both suites were also run under valgrind with no leaks.

One more check needs Docker: meson test --suite live starts a throwaway PostgreSQL and runs the set aside database code against it. None of the unit tests touch the live API, and none may.
